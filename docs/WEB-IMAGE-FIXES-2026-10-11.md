# 网页生图修复 · 2026-10-11

状态：本地修复，未提交、未推送、未部署；没有调用真实付费模型或启动本机 iMessage 桥。

## 已确认原因

- `publish_web_image` 导入的 `mirror_saved_image` 根本没有实现，导致生成成功后在保存入口报 ImportError。旧 handover 所称“镜像保留”与代码不符。
- 图片保存前 pop 数据、标记 published，异常时无法再次发布；该异常被宽泛的聊天异常分支误报为“脑子转不动”。
- 纯图片后空文字回复仍触发额外模型请求。
- 前端抹掉后端具体错误，统一显示连接失败；重复 image 事件可重复插图；连接无 done 但有内容时缺少中断提示。

## 已修复

- 实现已连接线路的图片镜像入队，按 message_id 在事务内去重；只转发已保存图片，不重新生图。
- 镜像异常不影响网页保存和 image 事件；图片成功保存后才清掉临时数据。保存失败单独报告 image_save_failed，本轮不重新生成。
- 已出图的空文字回复不追加流式模型调用。后续文字失败保留图片，改报真实错误，不保存虚构的助手道歉消息。
- 401/403、429、其他 HTTP、超时、缺少图片数据提供固定且脱敏的错误说明；永久 4xx 的常用聊天调用不重复重试。图片模型配置加载异常不阻断普通聊天。
- 支持最多 3 次 HTTPS 图片下载重定向，每一跳验证公网目标，不携带模型密钥；没有盲目添加参数后重新 POST 生图。
- SSE 等待期间每 15 秒保活；异常也发 error/done。前端保留已收到内容、去重图片、展示准确错误并清理工具状态。
- 日志只传异常类型，不记录 repr(exc)、响应正文、图片地址或密钥。
