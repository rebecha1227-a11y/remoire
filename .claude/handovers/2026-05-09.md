## 关键决策及原因

- **备注改名用 fetchReply 而非新接口**：system 消息发给后端当普通文本处理，Connie 能理解语境自然回应，不需要后端新增消息类型
- **Connie 自主写日记方案**：不用"X 小时没聊天"判对话结束，而用"当天高置信度记忆 ≥ 3 条"作门槛——APScheduler 每天 23:00 检查，有内容才写，没事不硬凑
- **记忆系统集中在 Us 页面体系**：Us 页面放记忆摘要（当天 top-4）+ 「进入记忆宫殿」入口；记忆宫殿是新页面（全部记忆 + 筛选/编辑/删除 + 候选审核 tab）；设置页的记忆候选只做跳转

## 坑和注意事项

- 日记时间解析：后端存 UTC 无 Z 后缀，前端需手动 +Z 再 +8h（已处理但易忘）
- DiaryPage `unlock_attempt` 活动类型在 renderText 有支持但无代码产生此类 item——死分支
- `mcp_server.py` 依赖本地 SQLite，电脑关机后 Claude 移动端无法访问
- 日记动态排序用 `MM-DD HH:MM` 字符串字典序，跨年会乱

## 完整开发计划

### Phase A — 日记写入打通（最小闭环）
1. **后端加 POST /api/diary 路由**（diary.py）
2. **DiaryPage WritingEditor `saveEntry` 调后端**，保存成功后插入本地列表
3. **Connie 自主写日记**：APScheduler cron job 每天 23:00（Asia/Shanghai，即 UTC 15:00），检查当天高置信度记忆数 ≥ 3 → 调 LLM 生成日记 → 写入 diary 表。幂等保护：写入前查 `SELECT 1 FROM diary_entries WHERE author='connie' AND source='auto' AND created_at >= 当天上海零点对应的UTC(前日16:00Z) AND created_at < 次日上海零点对应的UTC(当日16:00Z)`，已有则跳过
4. PIN 锁/解锁持久化（可选，不阻塞主流程）

### Phase A2 — 聊天页面增强

**执行顺序：先 A2-1 图片发送（明天第一项）→ A2-2 模型预设 → A2-3 思考链**

### Phase A2-1 — 图片发送（最先做，用户明确要求）
1. **ChatPage + 号面板**：「图片」按钮点击 → 调用 `<input type="file" accept="image/*">` 选择图片
2. **图片预览**：选中后在输入框上方显示缩略图预览，可取消
3. **发送**：图片 base64 编码随消息一起发到后端（或 multipart upload）
4. **后端**：接收图片，如果当前模型支持 vision 则作为 image content 传给 LLM，否则提示不支持
5. **气泡展示**：用户发送的图片消息在气泡里显示图片

### Phase A2-2 — 模型预设系统
1. **后端新增 `/api/settings/model-presets` 路由**：CRUD 模型预设（每个预设包含：昵称、api_key、base_url、model_name、provider）

3. **后端新增 `/api/settings/slots` 路由**：存取三槽位配置（daily / deep / backend），每个槽位关联多个预设，标记哪个是当前选中
4. **重构 ModelSettings（SettingsSubPages.jsx）**：
   - 上半部分：模型预设库管理（添加/编辑/删除预设，填 api_key + base_url 后自动拉取模型列表，给预设起昵称）
   - 下半部分：三槽位配置，每个槽位下拉选择已有预设，可添加多个，选中标记当前使用
   - 每个槽位可开关 Extended Thinking
5. **后端 `chat_service.py` / `llm.py`**：发送消息时读取当前槽位 + 选中预设的配置调用对应模型

### Phase A2-3 — 聊天输入栏模型指示器 + 思考链
1. **ChatPage 输入框右侧**：新增模型指示器按钮，显示当前模型名 + 模式（日常/深度）+ Extended Thinking 状态
2. **点击展开选择器**：可切换日常陪伴 / 深度时刻模式，在当前模式的预设列表中切换模型，开关 Extended Thinking
