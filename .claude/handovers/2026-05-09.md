## 关键决策及原因

- **日记互动用统一表 `diary_interactions`**：比单独建 comments/unlock_logs/notifications 更适合当前原型，动态流和留言板都能复用。
- **Connie 日记解锁是“请求—回应”机制，不用 PIN**：PIN 适合静儿自己的私密日记；Connie 的上锁日记应体现关系里的许可，而不是密码校验。
- **同意后永久解锁**：静儿明确选择“同意后永久解锁”。`respond_unlock(grant=True)` 会把 `locked=false` 写回 `diary_entries`。
- **前端不提供“Connie 同意/拒绝”手动按钮**：避免静儿替 Connie 做决定；Connie 应通过工具或后续自动/聊天流程回应。
- **静儿日记下 Connie 可主动评论**：写日记后会自动生成一条 Connie 评论，满足“每篇日记下面有互动评论区”。
- **工具使用改成意愿型，不是任务型**：日记/纸条是 Connie “想留下”，不是每次聊天后的完成项；通过 prompt + 后端节流双保险。
- **保留 `fastapi==0.136.1`**：当前 venv 已升级，requirements 必须同步，否则下次重装会回到不兼容组合。

- **后端启动方式**：用 `cd ~/Desktop/Remoire/backend && source venv/bin/activate && uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`，不要用系统 Python。

- **Connie 自动评论会调 LLM**：如果 API 不可用，会写 fallback 评论；不会阻塞核心留言写入太久。
