### 1. 记忆宫殿：手动编辑记忆内容

**问题**：记忆宫殿里每条记忆只能查看、移动层级、删除，但不能编辑内容。LLM 提取的记忆有时不够准确或有误，静儿没办法修正。

**做了什么**：
- 在 `MemoryItem` 组件中新增编辑模式：点击记忆展开后，操作栏多了一个「编辑」按钮
- 点编辑后内容变成 textarea，可以直接修改文字
- 保存调用 `PUT /api/memory/{id}` 接口更新数据库，页面即时刷新
- 取消则恢复原内容，不发请求

**后端情况**：`PUT /api/memory/{memory_id}` 接口原本就存在（支持更新 content、tags、layer、memory_type 等），只是前端没有调用入口。这次只改了前端。

**改动文件**：
- `frontend/src/components/MemoryPalace.jsx`：`MemoryItem` 新增 editing/editContent/saving 状态 + textarea 编辑 UI + handleSave 逻辑；`LayerDetail` 新增 `handleEdit` 函数并传给 `MemoryItem`

**交互流程**：点记忆展开 → 点「编辑」→ textarea 里改内容 → 点「保存」（或「取消」）

### 2. 主动消息时间感知增强

**问题**：Connie 主动发消息时搞不清当前时间。比如下午 13:33 问静儿"醒了没"，明明之前的聊天还在说吃早饭的事。主动消息走的是 daily 槽位（GLM 5.1），模型较弱，容易忽略时间上下文。

**根因分析**：
1. `autonomous.md` prompt 开头写的是"你现在醒来了"——模型看到"醒来"容易联想到对方也在睡觉
2. 时间信息 `{time_info}` 埋在 prompt 中间，不够醒目
3. 最后发给模型的 user message 里没有时间信息，模型在生成回复前最后看到的内容里缺少时间提醒
4. 聊天记录（15 条）虽然注入了，但没有明确指示模型要根据聊天内容推断静儿状态

**做了什么**：
1. `autonomous.md`：
   - 去掉"你现在醒来了"措辞，改为"你现在有自己的时间"
   - `{time_info}` 移到 prompt 最顶部第一行（原来在第 5 行）
   - 新增「时间感知（最高优先级）」规则块——明确要求根据时间+聊天记录推断静儿状态，举了正反例，禁止问与时间矛盾的问题
   - 发消息选项增加"消息内容必须与当前时间和最近聊天语境一致"
2. `nudge_service.py`：最后的 user message 中注入 `{time_info}`，并追加"根据当前时间和上面的聊天记录判断静儿的状态"提醒

**改动文件**：
- `backend/app/prompts/autonomous.md`
- `backend/app/services/nudge_service.py`

**设计决策**：静儿选择先靠 prompt 改善（方案 B），暂不把主动消息切到 deep 槽位（Opus 4.6），以控制成本。如果 GLM 5.1 仍然犯时间错误，再考虑换模型。

### 3. DSML 标签清理（nudge_service.py 中已有的未提交改动）

DeepSeek 模型有时在输出中混入 `<|DSML|>` 标签残留。之前已有清理逻辑但未提交，本次一并提交。

**改动文件**：
- `backend/app/services/nudge_service.py`：`full_reply` 和 `monologue` 中增加 DSML 标签正则清理 + 多余空行压缩
