### 2. 修复日记留言回复固定模板问题

**问题来源**
- 静儿给 Connie 日记留言后，Connie 回复永远类似：
  > 我看到啦。你写下来的这一点，我会好好接住。
- 这不符合预期。Connie 应该根据留言内容、日记内容、最近聊天、记忆、identity/voice 等上下文自然回复。

**根因**
- `generate_connie_reply()` 的 LLM 调用失败会静默 fallback 到固定句
- 原 prompt 很薄，只包含日记标题/内容/留言，没有加载 identity、voice、最近聊天、相关记忆、同篇留言历史
- 日志原本不记录失败原因，表面看像“回复正常但很机械”

**本日改动**
- 日记留言回复生成现在会注入：
  - `identity.md`
  - `voice.md`
  - 相关记忆（`memory_service.recall()`，limit=5）
  - 最近 12 条主聊天消息
  - 同篇日记下最近最多 8 条旧留言
- prompt 明确要求：
  - 必须根据日记内容、静儿留言、相关记忆、最近聊天和 Connie 性格来回
  - 不要使用模板句
  - 不要泛泛说“接住”
  - 不要复读静儿
  - 语气亲密自然，像 Connie 本人，通常 30–100 字
- LLM 调用失败会 `logger.warning(...)`，不再完全静默

**隐私保护补强**
- Connie 自己的上锁日记：只要数据库 `locked=True`，无论是普通留言还是申请解锁，都不会把正文送进 LLM
- prompt 明确：上锁日记不能透露正文细节、标题以外内容、隐藏情绪或具体事件
- 注意：
  - 静儿猜 PIN 成功只代表本次能看，不会把 `locked` 改成 false
  - Connie 同意解锁（`respond_unlock(... grant=True)`）会永久设置 `locked=False`，之后才允许留言回复读取正文

**容错补强（多轮评审后完成）**
- `get_diary()` 安全包装：DB 异常时 fallback，不打断留言接口
- `should_auto_reply()` 安全包装：自动回复判定失败时只跳过回复，不影响留言落库
- `memory_service.recall()` / 最近聊天读取 / 留言历史读取 / prompt 文件读取都安全降级为空上下文
- 上下文拼装使用 `.get()` 和字符串转换，防止脏数据缺字段时崩溃
- 自动回复“生成 + 写入”整体封装成 `_safe_create_connie_reply()`：Connie 回复失败或写入失败只打 warning，不影响静儿留言创建成功
- 当前刚创建的静儿留言会从“已有留言历史”中过滤，避免同一内容在 prompt 中重复出现导致复读

**当前行为**
- 用户留言先落库
- Connie 自动回复属于 best-effort：能生成就写入，失败只记日志
- 固定 fallback 只应该在 LLM 配置缺失/调用失败/异常时出现
- 如果还出现固定句，先看后端终端是否有：`生成 Connie 日记留言回复失败` 或 `Connie 日记自动回复生成或写入失败`

**涉及文件**
- `backend/app/services/diary_interaction_service.py`

### 4. 后端 reload 注意事项

**现象**
- 终端出现：
  ```text
  WARNING: WatchFiles detected changes in 'venv/lib/python3.11/site-packages/...'. Reloading…
  ```

**解释**
- 这不是报错，是 `uvicorn --reload` 监测到文件变化后自动重启后端
- 但它监测到了 `venv/` 里的第三方包文件，不理想，可能导致反复 reload

**建议启动方式**
```bash
cd ~/Desktop/Remoire/backend
source venv/bin/activate
uvicorn app.main:app --reload --reload-dir app
```

这样只监听 `backend/app`，不会因为 `venv` 文件变化反复重启。

### Phase B — Us 页面 + 记忆宫殿 + 记忆系统升级（核心体验）

#### 记忆系统升级（对应 `docs/MEMORY_UPGRADE_PLAN.md` Phase A）

1. **实现真正 `resume()`**
   - 每次对话开始/恢复时浮现关键上下文
   - 内容包括：
     - unresolved 记忆
     - 最近高 arousal 事件
     - 今日特殊日期
     - pinned 锚点记忆
   - 注入 system prompt
   - 当前 MCP 里有基础 `resume()`，但主聊天 prompt 里的深度 resume 仍未完成

2. **`recall()` 加入 weight/arousal 维度**
   - 当前主要是 bigram + 关键词 + tag 匹配
   - 要把情感强度、重要性、最近触发纳入评分
   - 高权重记忆在语义相近时优先浮现

3. **补全 `memory_type`**
   - 不再全部是 `fact`
   - 类型建议：
     - `fact`：稳定事实
     - `event`：发生过的事件
     - `date`：生日/纪念日/截止日等
     - `unresolved`：未完成的情绪/任务/承诺

4. **补全 valence/arousal 写入**
   - 记忆候选提取时让 LLM 同时标注情绪维度
   - `valence`：正/负情绪倾向
   - `arousal`：情绪强度/唤起度
   - 这些字段后续用于主动浮现、日记生成、recall 排序

5. **激活 `trigger_count` / `last_triggered_at`**
   - recall 命中时更新
   - find_associated 命中时更新
   - 用于判断哪些记忆经常被想起

6. **pinned 保护**
   - 核心记忆 `pinned=1` 不衰减
   - 核心关系锚点不要被自动合并/归档掉

7. **写入新记忆时继续保留 associated**
   - “写就是读”原则不能丢
   - 新记忆写入响应带 top-3 关联旧记忆
   - 前端可展示“这让我想起……”

   - 低权重、低触发记忆逐渐降权
