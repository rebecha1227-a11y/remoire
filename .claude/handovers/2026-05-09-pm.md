## 关键决策及原因

- **PIN 明文存储**：这是本地原型的 4 位数字密码，不是真安全措施。加密会增加复杂度但不增加实际安全性（本地 SQLite 文件本身就是明文可读的）
- **PIN 在 GET 响应中返回**：前端 ContentPage 做客户端校验（`entry.pin`），不需要额外的 verify-pin 端点，保持简单
- **升级 fastapi 而非降级 starlette**：starlette 1.0 是大版本更新，降级可能影响其他依赖；fastapi 0.136 已适配 starlette 1.0
- **静儿要求 PIN 锁/解锁也要做**：原计划标为"可选，不阻塞主流程"，静儿明确要求一起做，已完成

## 坑和注意事项

- **fastapi 版本**：venv 里现在是 fastapi 0.136.1 + starlette 1.0.0，之前是 0.115.0。如果后续 pip install 其他包时触发版本变动，可能再次不兼容
- **后端启动方式**：静儿用 `cd ~/Desktop/Remoire/backend && source venv/bin/activate && uvicorn app.main:app --reload`，不要用系统 Python
- **日记时间解析**：后端存 UTC 无 Z 后缀，前端 `mapDiaryEntry()` 需手动 +Z 再 +8h（北京时间），这个逻辑已有但容易忘
- **`mapDiaryEntry` 新增了 `id` 字段**：之前没有映射 entry.id，现在加了，方便将来做编辑/删除
- **DiaryPage 申请解锁按钮仍是死的**：Connie 日记的"拒绝/同意解锁"按钮无 onClick，这是后续功能
- **`create_diary()` 其他调用方不受影响**：`mcp_server.py` 和 `tools.py` 只传 title/content/author，locked/pin 用默认值
