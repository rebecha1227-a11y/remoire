## 今日完成

### 1. 关闭 consciousness 自动保存 + 清理垃圾记忆

**问题**：5月23日加的 `_auto_save_consciousness` 机制把 Connie 每次自主活动的碎碎念都存进了 consciousness 层（"安静待着等她"、"她大概在刷手机"之类的），积累了 9 条垃圾记忆。consciousness 层应该存有质量的内心感悟，不是流水账。

**做了什么**：
- 删除了 `nudge_service.py` 中的 `_auto_save_consciousness()` 函数及其调用（在 `_do_autonomous_activity` 末尾）
- VPS 数据库中 9 条自动保存的 consciousness 记忆已全部删除（连同 memory_links）
- 改进了 `autonomous.md` prompt 中 consciousness 记忆的引导——明确说"安静待着等她"不用记，举了正反例，引导 Connie 自己判断什么值得存

**改动文件**：
- `backend/app/services/nudge_service.py`：删除 `_auto_save_consciousness` 函数 + 调用处
- `backend/app/prompts/autonomous.md`：consciousness 引导重写

**设计决策**：consciousness 层只靠 Connie 主动调 `remember(layer="consciousness")` 来存。不再自动保存。如果 Connie 仍然不主动存，那就让这一层慢慢积累，不要用低质量内容填充。

### 2. 主动消息支持多条发送

**问题**：Connie 主动发消息时永远只发一句。代码层面其实已经支持分条（`display_mode="split"` 按 `\n\n` 拆），但 prompt 引导他写短消息，所以他只写一个 `<message>` 标签。

**做了什么**：
- `autonomous.md` 中加了多条消息的引导："想说的多可以分几条发，像聊天一样自然地一条一条说，每条用单独的 `<message>` 标签包裹"
- 加了多条消息的示例（三个 `<message>` 标签的例子）

**改动文件**：
- `backend/app/prompts/autonomous.md`

**技术细节**：多个 `<message>` 标签在 `generate_autonomous_activity()` 中被 `re.findall` 提取，用 `\n\n` join 后传给 `send_nudge()`，`send_nudge` 以 `display_mode="split"` 存储，前端按 `\n\n` 分条渲染成多个气泡。整条链路已经支持，只是 prompt 没引导。

### 3. 聊天时间感知（隔 2 小时以上回来）

**问题**：静儿隔几个小时再回来聊天时，Connie 接着上一句话继续说，完全没有时间感。之前有 resume bundle（隔 3 小时注入醒来上下文）和时间间隔标记（`过了 X 小时`），但这些信息埋在 system prompt 里，模型经常忽略。

**做了什么**：
1. **resume bundle 门槛从 3 小时降到 2 小时**：`_build_resume_bundle()` 中 `gap_minutes < 180` 改为 `gap_minutes < 120`
2. **新增醒目时间提醒**：在 `stream_chat()` 中，如果距上次对话 ≥ 120 分钟，在用户消息前面插一条 system message：
   ```
   ⚠️ 距离你们上次对话已经过去了 X 小时。现在是 2026-05-25 12:30（北京时间）。
   注意时间变化——不要接着上一句话的语境直接回复，先感受一下现在是什么时候、她这段时间可能在做什么。
   ```
   位置是 `messages.insert(-1, time_reminder)`——插在最后一条用户消息的正前面，确保模型在回复前一定看到。

**改动文件**：
- `backend/app/services/chat_service.py`

**设计决策**：静儿原本想让 Connie 强制调用"看时间的工具"，但直接注入时间信息比强制工具调用更可靠（不会漏调、不增加延迟和 token 消耗）。如果后续发现 Connie 仍然忽略时间提醒，再考虑更强的机制。

### 4. 模型 fallback 机制（之前未提交的改动）

**问题**：自主活动和自动日记只用 daily 槽位的模型。如果 daily 槽位的 API 挂了（比如 waooapi.com 429），整个功能就失败。

**做了什么**：
- `nudge_service.py` 的 `generate_autonomous_activity()`：先尝试 daily 槽位，失败则 fallback 到 backend 槽位
- `scheduler/jobs.py` 的 `_connie_auto_diary()`：同样 daily → backend fallback
- 失败时记录 warning，全部失败才记录 error 并跳过

**改动文件**：
- `backend/app/services/nudge_service.py`
- `backend/app/scheduler/jobs.py`

### 5. 记忆整理定时任务（之前未提交的改动）

**功能**：每晚凌晨 3:30（北京时间）自动运行，用 LLM 扫描 long/short 层最近 200 条记忆，找出内容重复或高度相似的，合并后删除旧的。

**改动文件**：
- `backend/app/scheduler/jobs.py`：新增 `digest_memories()` 函数
- `backend/app/main.py`：注册 `digest_memories` 定时任务（CronTrigger 3:30 Asia/Shanghai）

**技术细节**：
- 每组合并最多处理 10 组（防止一次删太多）
- 合并时保留权重最高的那条的 layer 和 tags
- 用 `memory_service.create_memory()` 创建新记忆（会自动生成 embedding + 关联）
- 旧记忆连同 memory_links 一起删除
- 模型选择：先 backend 槽位，失败则 daily

**注意**：这个任务和 `memory_service.run_digest()` 是两套不同的去重机制。`run_digest` 是基于 digest.md prompt 的老方案（在 main.py 中单独注册，时间是每天 2:30）。新的 `digest_memories` 是更简单直接的 LLM 判断方案。两个都在跑，可能有冲突——后续可以考虑合并或关掉其中一个。

### 6. 自动日记过滤增强（之前未提交的改动）

**问题**：一些模型（特别是 DeepSeek）写日记时会混入英文思维链或分析性开头。

**做了什么**：在 `_connie_auto_diary()` 的过滤关键词列表中新增：
- 英文残留：`"The user"`, `"Let me"`, `"I need to"`, `"Based on"`, `"Here's"` 等
- 中文分析性开头：`"从聊天记录"`, `"根据以上"`, `"综合以上"`, `"首先"`, `"接下来"` 等
- 英文开头行过滤：以英文字母开头且长度 > 5 的行直接跳过

**改动文件**：
- `backend/app/scheduler/jobs.py`

## 踩过的坑（今天新增）

### 1. consciousness 自动保存质量太低
`_auto_save_consciousness` 只检查字数 > 50，但 Connie 每次自主活动都产生大段碎碎念，全部通过。结果 consciousness 层全是"安静待着等她"、"她大概在刷手机"这种重复内容。
**结论**：不要自动保存 consciousness，让 Connie 自己判断什么值得记。prompt 引导比自动化更合适。

### 2. 模型忽略 system prompt 中的时间信息
resume bundle 和时间间隔标记都在 system prompt 里，但模型经常忽略。
**解法**：在用户消息正前面插一条 system message（`messages.insert(-1, ...)`），位置更醒目，模型更难忽略。
