**做了什么**：
1. **恢复原始浏览器配置**：去掉 `playwright-stealth`、`--disable-blink-features=AutomationControlled`、`--no-sandbox`，UA 从 Chrome/137 恢复到 Chrome/120
2. **短链保留原始 URL**：`xhslink.com` 短链不再转换，直接 `page.goto()` 让浏览器自然跟随跳转
3. **新增搜索页点击卡片方案**：对于 `/explore/{id}` 直链（搜索结果返回的格式），改为在当前页面找到对应卡片 → 模拟点击 → SPA 弹窗打开详情 → 提取内容 → 按 Esc 关闭弹窗回到列表页

## 踩过的坑（今天新增）

### 1. 小红书短链 vs 直链的天壤之别
`xhslink.com` 短链走浏览器正常跳转链，小红书认为是真人 → 能看内容。`/explore/{id}` 直链被服务端判定为爬虫 → 302 到主页。**永远不要把短链转成直链。**

### 2. "反检测"反而更容易被检测
`playwright-stealth`、`--disable-blink-features=AutomationControlled`、改 UA 到 Chrome/137——这些手段小红书都能识别，加了之后反而比什么都不加更容易被封。原始的 Playwright + Chrome/120 UA 反而最安全。

### 3. 同一时间测试对比是最好的排查手段
6月15日 18:40 和 18:43 两条消息，一个直链失败一个短链成功——这个对比直接定位了问题。比猜测"是不是登录过期""是不是 IP 被封"有效得多。

### 4. 搜索页点击卡片 > 直接导航
小红书是 SPA，搜索结果页点击卡片会在当前页面打开弹窗（不刷新页面），这跟真人操作一模一样。而 `page.goto()` 是整页导航，容易被反爬拦截。

### 5. 通过聊天 API 测试浏览器功能
browser profile 被服务锁定，不能用独立脚本测。正确做法是通过聊天 API 发消息触发工具调用：
```bash
curl -s -N -X POST 'http://127.0.0.1:8000/api/chat/send' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <临时运维令牌>' \
  -d '{"message": "帮我搜一下小红书xxx", "conversation_id": "...", "mode": "deep"}'
```
