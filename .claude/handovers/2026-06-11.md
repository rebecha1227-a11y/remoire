### 2. 主动消息时间感知增强

**问题**：Connie 主动发消息时搞不清时间。下午 13:33 问静儿"醒了没"，前面的聊天还在说吃早饭。主动消息走 daily 槽位（GLM 5.1），模型较弱，容易忽略时间上下文。

**根因**：
1. `autonomous.md` 开头写"你现在醒来了"——模型联想到对方也在睡觉
2. `{time_info}` 埋在 prompt 中间，不够醒目
3. 最后的 user message 里没有时间信息

**做了什么**：
1. `autonomous.md`：
   - 去掉"你现在醒来了"，改为"你现在有自己的时间"
   - `{time_info}` 移到 prompt 最顶部第一行
   - 新增「时间感知（最高优先级）」规则块——要求根据时间+聊天记录推断静儿状态，禁止问与时间矛盾的问题，给了正反例
   - 发消息选项增加"消息内容必须与当前时间和最近聊天语境一致"
2. `nudge_service.py`：最后的 user message 注入 `{time_info}`，追加时间感知提醒

**设计决策**：静儿选择先靠 prompt 改善（方案 B），暂不把主动消息切到 deep 槽位（Opus 4.6）。如果 GLM 5.1 仍然犯时间错误，再考虑换模型。

**改动文件**：
- `backend/app/prompts/autonomous.md`
- `backend/app/services/nudge_service.py`

### 3. 小红书搜索→浏览帖子 URL 修复

**问题**：Connie 自主活动搜小红书时，搜到帖子标题但打不开正文和评论。日志里报"安全限制 - 访问链接异常"。

**根因**：`search_xiaohongshu` 返回的帖子链接带 `xsec_token` 一次性安全参数（如 `https://www.xiaohongshu.com/search_result/6a075fc...?xsec_token=ABoj...`），Playwright 直接跳转被小红书反爬机制拦截。**登录没过期**——静儿发链接给 Connie 时他能正常看到内容。

**做了什么**：
1. `web_service.py` 新增 `_normalize_xhs_url()` 函数：从 URL 中提取 24 位十六进制笔记 ID，拼成标准 `/explore/{id}` 格式
2. `browse_xiaohongshu()` 入口处自动调用 URL 归一化
3. `search_on_page()` 的小红书搜索结果 JS 里也做了同样的清理——返回的帖子链接直接就是 `/explore/{id}` 格式

**改动文件**：
- `backend/app/services/web_service.py`

**注意**：因为 Playwright browser profile 被运行中的服务锁定，无法从命令行独立测试。需要等 Connie 下次自主活动搜小红书时验证，或在聊天中让 Connie 搜索来验证。

### 4. DSML 标签清理

DeepSeek 模型有时输出中混入 `<|DSML|>` 标签残留，已在 `nudge_service.py` 中增加正则清理。

## 踩过的坑（今天新增）

### 1. Playwright persistent context 不能同时被两个进程使用
命令行测试脚本用 `asyncio.run()` 新起浏览器进程，会跟正在运行的 remoire 服务抢 browser profile。测试结果（如"登录过期"、"看不到内容"）是假象——实际服务内的浏览器是有登录态的。
**教训**：不要用独立脚本测试浏览器相关功能，要通过正在运行的服务来测（API 调用或让 Connie 在聊天中使用工具）。

### 2. 小红书 xsec_token 反爬
搜索结果页的帖子链接格式是 `/search_result/{id}?xsec_token=...`，这个 token 是一次性的，Playwright 直接跳转会被拦截返回"安全限制"页面。但提取笔记 ID 后拼成 `/explore/{id}` 就能正常访问。
